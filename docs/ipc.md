# Daemon protocol

`lexiglanced` listens on `$XDG_RUNTIME_DIR/lexiglance/daemon.sock` (a Unix domain socket, owner only); a runtime
directory so deep that the path would not fit in a socket address moves it to `/tmp/lexiglance-<uid>-<hash>/daemon.sock`.
On Windows it listens on the named pipe `\\.\pipe\lexiglance-<username>` instead, on macOS on
`~/Library/Application Support/Lexiglance/run/daemon.sock` (not in `$TMPDIR`, which macOS clears of old files every
night). Messages are single-line JSON objects.

One daemon runs per user: it holds an exclusive lock on `$XDG_RUNTIME_DIR/lexiglance/daemon.lock`, which records its
pid. A second `lexiglanced` exits; `lexiglanced --replace` takes over instead: it asks the running daemon to shut down,
and ends it (SIGTERM, then SIGKILL) if it has not exited within five seconds. Daemons of other homes (`LEXIGLANCE_HOME`)
are left alone.
A daemon that is shutting down closes its socket first and ends itself if its threads have not stopped within four
seconds.

```
-> {"id": 1, "method": "lookup", "params": {"text": "食べた"}}
← {"id": 1, "result": {...}}          or   {"id": 1, "error": {"message": "..."}}
← {"event": "import.progress", "params": {...}}     (broadcast to every client)
```

A connection's requests are answered in the order they were sent. The ones that wait (`health`, `translate`,
`anki.add`, `audio.play`, `debug.capture`, `debug.pointer`) are worked on beside everything else, so they hold up no
other connection: a client that wants quick answers meanwhile asks over a second one.

## Events

`config.changed`, `status.changed`, `dictionaries.changed`, `import.started`, `import.progress`,
`import.finished`, `keys.recorded`, `trigger.changed` (`{held}`: the trigger chord was pressed or let go) and
`capture.result` (`{summary, where, window, found, entries}`: what the latest lookup on screen read, and in which window class, a few times a second at
most) and `health.progress` (`{checking, done, total}`: the part of the health check being worked through, sent as
each begins).

The `debug.*` methods (but `debug.simulate` with no problems, which takes them away) and subscribing to events answer
only while developer mode is on (`"developer": true` in the settings); otherwise they fail, and subscriptions stop when
it is turned off. They hand out the screen, the log and what was looked up to any client of the user.

Only to the connections that subscribed to them (`events.subscribe`), and made only while one has: `trace`
(`{id, time, stages: {<stage>: {ms, p50, p95}}, ...}`, one for each stage of a lookup as it is done; `id` is the
request's generation, the capture's event adds `kind, x, y, window, source, text, unread, offset, rewound, confidence,
characters, found, matched, language`, see [debugging.md](debugging.md)) and `log.line` (`{level, line}`: a line
written to the daemon's log).
